# streaming-rt60

ADR-0005 の V7。ローリング窓のRT60推定が1チャンクあたりに使う時間を、ストリーミングループの500ms予算に対して測る。

この設計は毎チャンク3秒窓全体に `find_decay_events` をかけ直すので、「重いのではないか」が最初に来る疑問になる。それに数値で答えるためのもの。

## 実行

```
.venv/bin/python benchmarks/streaming-rt60/run.py
```

## 結果（2026-09-22、Apple Silicon / Python 3.13.12 / 合成信号6条件 × 5回）

| RT60 | ポーズ | mean | p95 | max | 500msに対する割合 |
|---|---|---|---|---|---|
| 0.3 | 0.7s | 0.91ms | 1.26ms | 1.52ms | 0.30% |
| 0.6 | 0.7s | 0.94ms | 1.37ms | 1.42ms | 0.28% |
| 1.0 | 0.7s | 1.05ms | 1.45ms | 1.68ms | 0.34% |
| 0.3 | 1.2s | 0.88ms | 1.12ms | 1.13ms | 0.23% |
| 0.6 | 1.2s | 0.91ms | 1.20ms | 1.35ms | 0.27% |
| 1.0 | 1.2s | 0.97ms | 1.31ms | 1.34ms | 0.27% |

**最悪ケース 1.68ms = 500msチャンクの 0.34%。** ADR-0005 の反証条件は「現行比10倍超」だったが、現行の `_extract_decay_segment` は遷移が起きたときしか走らないため比較の分母が定義できない。代わりに実時間予算に対する割合で記録する。

残響が長いほどわずかに増える（減衰イベントが長くなり、T20フィットの対象サンプルが増えるため）が、0.3秒と1.0秒の差は0.1〜0.15ms程度。
